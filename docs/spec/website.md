# kotan-website 仕様（種）

この文書は、デザイン・実装に入る前の合意事項をまとめたものである。詳細な文言・画像・リンク一覧は資料追加後に更新する。

## Why（なぜ）

- 内定同期・入社同期・社員との交流が増えるなかで、「私はこういう人間です」を自分の言葉と実績で伝えたい。
- 既存の `kotan-portfolio` の配色は残しつつ、デザインはリニューアルし、名刺代わりかつ人となりが伝わる個人サイトにする。
- 入社直後は価値観と人柄の比重が大きく、経験を積むにつれてアウトプット中心に厚くしていける形にしたい。

## What（何を）

### 読者

- 主: 内定同期 / 入社同期・社員
- 副: それ以外の知人・社外の人（転職訴求はしない）

### 伝えたい自己像

- 「割となんでもやりたいが、なんでも出来るわけじゃないジュニアエンジニア」
- 「こういうアウトプットをする人」と「こういう価値観の人」の両方
- 時間経過とともにアウトプットの比重が増えてよい

### トーン・ビジュアル

- 基調色: `#606da1`（`kotan-portfolio` 由来）
- 雰囲気: 親しみやすい温かさ ＋ 前向きさ
- レイアウト: 複数セクションの縦長1ページ
- 参考構成（見た目は別物）: [https://info-kotomin-owf9sr.laravel.cloud/](https://info-kotomin-owf9sr.laravel.cloud/)
- UI 資産は全部新規（portfolio は色・文言などの参照のみ）

### ページ構成（セクション）

1. **ヒーロー** … 名前、一言（上記の自己像）、主要リンク、顔写真（任意）
2. **価値観 / About** … エンジニアとしての価値観・大事にしていること
3. **コミュニケーションってどういうもの** … 感音性難聴であること、よく使う手段（日本語対応手話など）、周囲が知っておくと関わりやすいこと。詳細な調整依頼リストの全文転載は必須としない（要約＋必要なら詳細への導線）
4. **いまの自分** … 経歴・インターン・研究・これから社会人としてのスタンス
5. **アウトプット** … 制作物・登壇・発表・学園祭などの仕組みづくり・研究など。カテゴリ分けできること。将来、記事 URL 追加で増えていく想定
6. **私的な面** … 趣味・興味・話しやすい話題（公開制限は特になし。内容は後日追記）
7. **コンタクト** … SNS / 連絡手段（転職・カジュアル面談 CTA は置かない）

### コンテンツ運用

- 本文・経歴・アウトプット一覧などは **Markdown（または同等のデータ）でメンテ**する
- 見た目・レイアウト・動きは Markdown に閉じ込めず、コンポーネント側で自由に表現する
- 将来オプション: note / Qiita などの URL を POST するだけでアウトプット一覧が更新される。反映は再デプロイ（数分遅れ）でよい。初期リリース必須ではない

### 技術方針（決定）

- スタック: **Astro**（TypeScript。インタラクションが必要な箇所のみ必要に応じて React 等を併用してよい）
- スタイリング: **Tailwind CSS v4**（`kotan-portfolio` と同じ構成に揃える）
- 出力: 静的サイトとしてデプロイできること
- ホスティング: **GitHub Pages**（決定）。GitHub Actions で `main` への push から自動ビルド・デプロイする
  - リポジトリは `Kotan-86/kotan-website`（プロジェクトページ）となるため、公開 URL は `https://kotan-86.github.io/kotan-website/`。Astro 側は `base: '/kotan-website/'` の設定が必要
- ドメイン: 初期は上記の無料サブドメインで公開。独自ドメインの取得は後日検討（対応する場合も静的ホストの前提は崩さない）
- リポジトリ: 本リポジトリ `kotan-website` に新規構築。`kotan-portfolio` は改修しない

### 公開目標

- **入社前の公開を目指す**（正確な入社日・締め切りは別途確定）
- 全セクションを同時に完成させるより、資料が揃った箇所から順次拡充してよい。ただし「ヒーロー／価値観・About／コミュニケーション／コンタクト」は初期公開に必須、「いまの自分／アウトプット／私的な面」は簡易版でも可とし、後から厚くする

### 参照資料（後日・詳細埋め用）

- サポーターズ記載プロフィール（経歴・自己PR・制作物・スキル・リンク）
- 「齋藤のコミュニケーションってどんなもの!」（コミュニケーション節の元資料）
- その他、ユーザーが後から渡す画像・文言・リンク

### 初期リリースでやらないこと

- 実装・デザイン本番制作（本仕様確定・資料充足の後）
- 記事 URL POST による自動更新（将来オプション）
- 転職活動向けの訴求セクション
- 多言語対応（現時点では日本語のみ想定）

## 未決・後続

- ヒーロー用写真・私的な面の具体トピック
- アウトプットの初期掲載リストとカテゴリ名の確定
- 独自ドメインを取得するかどうかの最終判断（初期はサブドメイン運用）
- 連絡先に載せるチャネルの確定
- 入社日・公開締め切りの具体的な日付
- OGP（SNS シェア時のタイトル・説明・画像）の内容
- アクセシビリティの具体対応（コミュニケーション節の性質上、画像 alt・コントラスト比・キーボード操作などは通常より丁寧に検討する）
- アクセス解析ツールを入れるか（入れる場合はプライバシー配慮の方針も合わせて決める）

## 目的(Why)

〔出典: issue #35 の Why〕

- 現在は、1ページの中に、性質の異なる情報のまとまりがまとめて掲載されている。
- 情報量として過多であるうえに、内定同期に見せるもの、社員に見せるもの、万が一市場に出るときに見せるものが混ざっている。
- このままでは、閲覧者が何をどこで見ればいいかが分からなくなる。
- そのため、情報をカテゴリにまとめ、閲覧対象ごとに必要な情報へスムーズにアクセスできるようにする。

プロダクトゴール([docs/product-goal.md](../product-goal.md))の「初対面の人やオンライン上で交流する人が、…前向きな印象形成をスムーズに構築できる状態にする」に対し、情報の見通しを良くすることでつながる。

## 実現内容(What)

### ユーザーから見えるもの

1. サイトは、カテゴリごとの5つのページ「経歴」「いま」「これまで」「これから」「日常」からなる。経歴のページがトップ(`/kotan-website/`)で、他の4ページのパスは `now/`・`past/`・`future/`・`daily/`(出典3 Q2)。〔出典2・3〕
2. 固定ヘッダーの下段の項目は、5つのカテゴリ(経歴 → いま → これまで → これから → 日常 の順)になる。各項目を選ぶと、そのカテゴリのページへ移動する。ヘッダーは5ページのすべてに同じ形で表示される。〔出典1・2〕
3. ヘッダーでは、いま開いているページの項目が、他の項目と見た目で区別でき、支援技術からも「現在のページ」と分かる。〔出典3 Q4〕
4. ヘッダーの上段のタイトル「こーたんプロフィールサイト」は、トップ(経歴)のページへのリンクになる。〔出典3 Q4〕
5. 各ページに載るものは次のとおり。〔出典2・3〕

   | 経歴(トップ) | ヒーロー | 僕のコミュニケーション方法 |
   | いま | カテゴリ名の見出し(`h1`)と、文「準備中です。」 | (なし) |

### spec-designer が具体化した点(承認済み: 2026-10-08)

- **「これまで」の中の並び**: 現在の1ページの並び(活動歴 → アウトプット)を保つ。
- **ページの題名(`<title>`)**: トップのページは「こーたんプロフィールサイト」のまま。他のページは「<カテゴリ名> | こーたんプロフィールサイト」。
- **サイト名の定義は1か所**: サイト名「こーたんプロフィールサイト」は、現在トップのページとヘッダーの2か所に書かれている(feasibility 軽微10)。本PBIで、ヘッダーのタイトル・トップの題名・他のページの題名の組み立てがすべて参照する1か所(カテゴリの定義の近く)にまとめる(PBI-004 の「文言は1か所の定義」)。
- **ヘッダーの項目名とアイコン**: 項目名はカテゴリ名(経歴 / いま / これまで / これから / 日常)。カテゴリ名は1か所に定義し、ヘッダーとページの両方がそこを参照する(PBI-004 の「文言は1か所の定義」)。アイコンは `material-symbols-light` のセットから選び、依存を増やさない。候補(実在は確認済み): 経歴 = `badge-outline`、いま = `today-outline`、これまで = `history`、これから = `trending-up`、日常 = `interests-outline`(現在の「趣味・日常」のアイコン)。それらしいかは PO確認で判定する。
- **ヘッダーの形**: 2段(上段にタイトル、下段に項目を左寄せ)、768px 以上はアイコン + 項目名、767px 以下はアイコンだけ、フォント・色・高さ・ホバーとフォーカスの下線は、PBI-008 の確定版と同じにする。
- **ヘッダーの高さ 73px を保つ**: ヘッダーの高さは、PBI-008 の確定版の 73px のまま変えない(ページ内のリンク先の見出しが隠れないための上側の余白 5.5rem と対応している。AC-11・AC-18 の前提)。現在のページの印は、項目がすでに持っている(透明の)下線の**色だけ**を切り替えて出し、項目の大きさを変えない。タイトルをリンクにしても、タイトルの下線(ホバー・フォーカスのとき)でヘッダーの高さを変えない。`nav` の名前は「ページ内の目次」から、ページ間の移動を表す名前(例: 「カテゴリ」。文言は実装判断)に改める。
- **現在のページの見た目**: 現在のページの項目には、ホバー・フォーカスのときと同じ下線を常に出す。色だけに頼らない。既存の色トークンだけを使い、項目の大きさ・位置は他の項目と変えない(ヘッダーがずれない)。767px 以下(アイコンだけ)でも下線で見分けられる。
- **タイトルのリンク**: タイトルの文言・フォント・色・位置は PBI-008 の確定版のまま。ホバーとフォーカスのときは、項目と同じ形の下線で、リンクであることが分かる。タイトルは `nav` の項目に数えず、`aria-current` も付けない。
- **リンク先の名前(`#<名前>`)**: 5つのセクションは、移動先のページでも、今の名前(`hobbies` / `activities` / `communication` / `outputs` / `thoughts`)を持ち続ける(例: `/kotan-website/past/#activities` で活動歴の見出しへ移動できる)。
- **トップ以外の4ページの `h1` の見た目(承認事項)**: 文字の大きさと太さはヒーローの名前の `h1` と同じ(太字。どの幅でもセクションの見出し `h2` より大きい)、色はセクションの見出し `h2` と同じ本文の色トークン、位置はセクションと同じ左端・最大幅の列に左寄せ。
- **ページ共通の部品**: 5ページに共通の骨組み(ヘッダーへの現在のページの受け渡し、`main` の左右の余白、セクション間の 48px、ページ最下部の 4rem、トップ以外の `h1` とその上下の 48px)は、1つの共通部品(例: `CategoryPage.astro`。カテゴリを受け取り、トップ以外では `h1` を出し、トップではヒーローを受け取る)にまとめ、各ページはそれを使う。余白の指定がページごとにずれないようにするため。`BaseLayout.astro` は変更しない。部品の名前と受け口は実装判断(tasks の公開IFで固定する)。
- **余白**: 各ページの最後のセクション(「いま」のページでは文「準備中です。」)の下に、ページ最下部の空き(4rem)を置く。セクション間の余白(48px)は今と同じ。トップでは、ヒーローの上下の空きは PBI-008 の約束(ヘッダーの下端から 48px)のまま。他の4ページは、ヘッダーの下端から `h1` の上端まで 48px、`h1` の下端から最初のセクションの見出しの上端まで 48px とする。

## 受入基準(承認済み: 2026-10-08)

> 検証方法の凡例 — `自動テスト`: テストコマンドで機械的に判定できる。`AI実行`: 開発者エージェントがコマンドを実行し、出力やファイルを観測して判定できる。`PO確認`: ブラウザでの見た目・操作の確認を PO が行う。
>
> 「5ページ」は5つのカテゴリのページ、「確認する幅」は 375px・767px・768px・1280px を指す。ページのパスは、経歴(トップ)`/kotan-website/`、いま `/kotan-website/now/`、これまで `/kotan-website/past/`、これから `/kotan-website/future/`、日常 `/kotan-website/daily/`(出典3 Q2)。

### 構造(ビルド成果物)

1. **5ページがある**: `npm run build` の成果物に、5ページの HTML がちょうど5つあり、それぞれが上記のパスで配信される位置にある。5ページ以外のページ(例: 6ページ目のトップ、`career/`)は無い。〔検証: AI実行(`dist/` を読む)〕

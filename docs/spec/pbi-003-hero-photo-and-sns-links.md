## 目的(Why)

プロダクトゴール「初対面の人やオンライン上で交流する人が、僕自身の身の丈に合った前向きな印象形成をスムーズに構築できる状態にする」([docs/product-goal.md](../product-goal.md))に対して、現在のページは「名前」と「一言」というテキストだけで構成されている。

- **名前と顔とイメージカラーが一致していない。** 名前だけでは、実際に会ったときの人物像と結びつかない。顔写真を、確定済みのイメージカラー([docs/spec/pbi-002-warm-background-color.md](./pbi-002-warm-background-color.md))の上に置くことで、「よりリアルな前向きな印象形成」を促す。〔出典: issue #2 の Why〕
- **サイトの外に出る導線がない。** 現在のページには外部リンクが1つもなく、読者が「この人のアウトプットを見たい」と思っても行き先がない。SNSへの導線を置くことで、印象形成が1ページで終わらず、継続的な接点につながる。
- 本PBIは、[docs/spec/website.md](./website.md)「ページ構成(セクション)」の第1項「ヒーロー … 名前、一言、主要リンク、顔写真(任意)」のうち、PBI-001 で対象外とした **顔写真と主要リンクを解禁する**ものである。ヒーローセクションをこの PBI で完成形に近づけ、第2〜7セクションは後続PBIで積み増す。

### 顔写真

1. **顔写真が表示される**: ローカル開発サーバ(`npm run dev`)でトップページを開いたとき、PO から受領した顔写真(573x573 の JPEG)が表示され、読み込み失敗(画像の代替表示)にならない。〔検証: PO確認〕
2. **顔写真が丸型で、顔全体が収まっている**: 顔写真が完全な円(縦横比 1:1、角が丸いだけの四角形ではない)として表示され、**こーたん本人の頭部(髪の生え際から顎まで、および両耳)が円の内側に収まっている**(顔の一部が円の外で切れていない)。〔検証: PO確認〕
3. **第三者が識別できる形で写っていない**: 円の内側に見える範囲に、**個人を識別できる第三者の人物が写っていない**。背景の店内(椅子、テーブル、掲示物、グラス等)の写り込みは許容する。〔検証: PO確認〕
   - 補足(判断の材料): spec-designer が画像を拡大して点検した結果、**個人を識別できる第三者は確認できなかった**。ただし画像上端中央付近と右端に、強くぼけて個人を特定できない「人物の可能性がある輪郭」がある(前提節の観測事実を参照)。円形トリミングの範囲によってはこれらが円内に入るため、**最終判断は PO が行う**。
4. **画像に代替テキストがある**: ビルド成果物の HTML において、顔写真の `img` 要素に `alt="こーたん（齋藤 光貴）の顔写真"` が設定されている(文字列として一致)。〔検証: AI実行(`npm run build` の出力 HTML を読む)〕
5. **画像がリポジトリに含まれている**: 顔写真ファイルが git 管理下(`src/assets/` または `public/`)に存在し、`.work/` 配下を参照していない。`npm run build` の出力 `dist/` に画像ファイルが含まれる。〔検証: AI実行(`git ls-files`、`dist/` の確認)〕

### 設計メモ(実装者への申し送り。実装方法の指定ではない)

- **PBI の大きさ**: [CLAUDE.md](../../CLAUDE.md) の基準は「PBI全体で3コミット程度、1コミットあたりの実装コード変更 300 行まで」。本PBIの実装コードの変更は `src/pages/index.astro` の書き換えと SNSリンクのデータ・コンポーネント追加が中心で、この範囲に収まる見込みである。収まらないと判明した時点で、分割(例: 「顔写真の2カラム配置」と「SNSリンク」)を PO に提案すること。
- **顔写真のトリミング**: 元画像は 573x573 の正方形で、内接円に頭部が収まることを仕様側で確認済み。円の表示直径が **286px を超える**設計にすると、高解像度ディスプレイで元画素が不足しうる(573 ÷ 2 = 286.5)。超える必要が出た場合は、実際の見え方を確認し、粗さが問題になるなら `needs-decision` とすること。
- **アイコンの扱い(2026-09-23 改訂)**: アイコンは PO 提供の公式ロゴのファイルを使う(AC-13)。アイコンライブラリを依存に追加すると AC-18 に抵触する。

  - **GitHub / note**: SVG と PNG のどちらでもよい。
  - **AC-17 との関係**: ロゴの SVG の中身を `.astro` にインラインで書き写すと、ロゴ内の色指定(例: note の `#040000`・`#EBEBEB`)が `.astro` に16進値として入り、AC-17(`.astro` に16進値を直書きしない)に抵触する。ロゴはファイルとして置いて参照すること。

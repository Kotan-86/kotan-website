## 目的(Why)

プロダクトゴール「初対面の人やオンライン上で交流する人が、僕自身の身の丈に合った前向きな印象形成をスムーズに構築できる状態にする」([docs/product-goal.md](../product-goal.md))に対して、現在のページは、ヒーロー、趣味・日常、活動歴、僕のコミュニケーション方法で構成されている。

- 当たり障りのない話題だけでも最初の会話は始められるが、それだけでは入社後にどんなことを考えている人なのかまでは分からない。〔出典: issue #24 の Why〕

### 設計メモ(実装者への申し送り。実装方法の指定ではない)

- **PBI の大きさ**: [CLAUDE.md](../../CLAUDE.md) の基準は「PBI全体で3コミット程度、1コミットあたりの実装コード変更 300 行まで」。本PBIの実装は、コンポーネント1つ(PBI-006 の趣味・日常と同程度で約30行)、文言の定義1つ(約30行)、`index.astro` への組み込みと仕様コメント(10行未満)、コミュニケーション節の下側の余白の変更(数行)で、1〜2コミット・合計100行程度に収まる見込みである(未確認: 既存ファイルの行数からの見積もり)。website.md・README の更新は行数に数えない。**実装の着手条件(R-5 の承認)は満たされた**(2026-09-24。R-1〜R-5 すべて決定済みで、7つの文字列はすべて確定文言)。
- **文言の一致(AC-6)**: カード2の本文には全角の「？」(U+FF1F)と、その直後の全角空白(U+3000。R-3 決定)が含まれる。半角の「?」や半角空白に置き換えない。ヒーローの一言の「なぜ?」は半角の「?」であり、本PBIの文言とは別物である(一言は変えない)。

- **セクション間の余白とページ最下部(AC-18。feasibility B-1)**: 現在、コミュニケーション節の下の内側余白がページ最下部の空きを作っていると読める(前提節。未確認: コードを読んだ推測)。最下部の空きを新セクションの下へ移す方法は、次のどちらでもよい(実装判断。どちらでも AC は同じ)。
  - 方法1(直接編集): `CommunicationSection.astro` の下側の余白の指定を外し、新セクションの下に同じ大きさの空きを持たせる。ファイル先頭のコメントの追随が要る。了承2(了承済み。この方法を選んだ場合に限る)の範囲で行う。AC-20 は「下側の余白の指定だけの変更を許容。ファイル先頭のコメントの追随を除く」。

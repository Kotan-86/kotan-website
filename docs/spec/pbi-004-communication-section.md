## 目的(Why)

プロダクトゴール「初対面の人やオンライン上で交流する人が、僕自身の身の丈に合った前向きな印象形成をスムーズに構築できる状態にする」([docs/product-goal.md](../product-goal.md))に対して、現在のページはヒーロー(顔写真・名前・一言・SNS 4件への導線)だけで構成されており、**実際に会ったときにどう関わればよいか**の手がかりが無い。

- 入社前や入社直後は、初対面や関わりの浅い社員・内定/入社の同期とコミュニケーションを取る機会が多い。〔出典: issue #3 の Why〕
- 目に見える手段でコミュニケーションを取るこーたんと、音や声でコミュニケーションを取る相手との間では、互いにノウハウが無いことが多い。〔出典: issue #3 の Why〕
- そのため相手はコミュニケーションに不安を持ちやすく、それを解消するニーズは大きい。事前に「こーたんが使う手段」「音声中心の場で起こりやすいつまずき」「こうしてもらえると関わりやすいこと」を知っておけば、相手は初回から具体的な関わり方をイメージでき、印象形成がスムーズになる。〔出典: issue #3 の Why〕
- 本PBIは、[docs/spec/website.md](./website.md)「ページ構成(セクション)」の第3項「**コミュニケーションってどういうもの**」を実装するものである。同書「公開目標」で、コミュニケーション節は**初期公開に必須**のセクションとされている。

## 実現内容(What)

### ユーザーから見えるもの

サイト(ローカル開発サーバおよび公開URL `https://kotan-86.github.io/kotan-website/`)のトップページで、ヒーローより後ろへスクロールすると、新しいセクション「**僕のコミュニケーション方法**」が表示される。現時点では、本セクションはヒーローの後に配置する唯一のセクションである。将来、website.md 第2項「価値観/About」が追加されるときは、ヒーローと本セクションの間に挿入されてよい(Q7)。

1. セクションの見出し「僕のコミュニケーション方法」がある。見出しはページ背景の上に置かれる(カードの外)。
2. その下に、**3つのサブセクション**が、すべての画面幅で**縦一列**に、次の順で並ぶ(Q5)。各サブセクションは、見出しと、その下の3項目の箇条書きで構成される。
   1. 目に見えるコミュニケーション手段を使っています
   2. 音声中心の環境では、こういうつまずきが起こりやすいです
   3. こうしてもらえると、お互い関わりやすいです
3. 各サブセクションは、**白地のカード**に載っている。カードはサブセクションごとに分かれ、カードとカードの間にはページ背景が見える(Q6、Q8)。
4. 各サブセクションの3項目は、行頭記号付きの箇条書きで表示される。画面幅が狭いときは、1項目が複数行に折り返してよい(Q4)。
5. 各サブセクションの箇条書きの文言は、「前提」節の確定文言のとおりである(文字を変えない)。診断名などの説明文は加えない(Q2)。
6. 本セクションの左端と最大幅は、ヒーローのブロック(顔写真・名前・一言・SNS 導線のまとまり)の左端と最大幅に揃う(Q5)。
7. 見出しの文字の大きさは、名前(ページの最上位の見出し)> セクションの見出し > サブセクションの見出し の順に小さくなり、見出しと本文を見分けられる。
8. 本セクションの文字(見出しを含む)はすべて本文色で表示され、その直下の背景(ページ背景またはカードの白地)に対して 4.5:1 以上のコントラストがある。
9. スマートフォン幅(375px)からデスクトップ幅(1280px)まで、はみ出しや重なりなく読める。
10. ヒーロー(顔写真・名前・一言・SNS 4件)の見た目と並びは変わらない。幅 1280 x 800px ではヒーロー全体が引き続きスクロールせずに見え、新しいセクションはスクロールした先に現れてよい。

### 支援技術から見えるもの

- ページの見出しの構造は、`h1`(名前)→ `h2`(僕のコミュニケーション方法)→ `h3`(サブセクション3つ)となり、見出しレベルの飛び越しが無い。見出しの一覧から、セクションとサブセクションへ移動できる。
- 各サブセクションの3項目は、3項目のリストとして読み取れる(Q4)。

### 配色の追加(ユーザーにはカードの白地として見える)

- カードの背景色として、**白 `#ffffff`** を新しいカラートークン `--color-card-background` として追加する(Q8)。ページ背景色との関係は「ページ背景色の混合式(基調色を白で 30% 混合)において、基調色の割合を 0% にした色 = 混合に使う白そのもの」である。

- 既存の3トークン(`--color-brand-primary`、`--color-bg-surface`、`--color-text-body`)の名前と値は変えない。

### 配置と見出しの構造

1. **ヒーローより後ろにセクションがある**(Q7): ビルド成果物の HTML で、本セクションの見出し「僕のコミュニケーション方法」が、ヒーローの要素(名前の `h1`、一言、SNS 導線4件の `a` 要素)のすべてより**後ろ**に出現する。ヒーローの要素どうしの間(例: 一言と SNS 導線の間)に本セクションの要素が入り込まない。ヒーローの「直後」であることは求めない(将来、ヒーローと本セクションの間に別のセクションが挿入されてよい)。〔検証: AI実行(`npm run build` の出力 HTML を読む)〕
2. **セクションの見出しが `h2` である**: ビルド成果物の HTML に `h2` 要素がちょうど1つ存在し、そのテキストが「僕のコミュニケーション方法」と完全に一致する。〔検証: AI実行〕
3. **サブセクションの見出しが `h3` である**(Q3): ビルド成果物の HTML に `h3` 要素がちょうど3つ存在し、文書の順に、テキストが次と完全に一致する。3つとも、AC-2 の `h2` より後ろに出現する。〔検証: AI実行〕
   1. 「目に見えるコミュニケーション手段を使っています」
   2. 「音声中心の環境では、こういうつまずきが起こりやすいです」
   3. 「こうしてもらえると、お互い関わりやすいです」
4. **見出しの階層が飛ばない**: ビルド成果物の HTML の見出し要素を文書の順に並べると、`h1`(1つ。テキストは「こーたん（齋藤 光貴）」で変更なし)→ `h2`(1つ)→ `h3`(3つ)となり、`h4`〜`h6` は無い。〔検証: AI実行〕
5. **サブセクションが3つのまとまりである**(Q1): ビルド成果物の HTML で、各 `h3` とそのサブセクションの本文3項目を、1つの要素がまとめて囲んでいる。その要素は、他のサブセクションの `h3` と本文の項目を含まない。囲む要素の種類(`div`、`section` など)、入れ子の深さ、`class` 名は問わない。〔検証: AI実行〕

- **PBI の大きさ**: [CLAUDE.md](../../CLAUDE.md) の基準は「PBI全体で3コミット程度、1コミットあたりの実装コード変更 300 行まで」。本PBIの実装は、トークン1つの追加、セクションのコンポーネント1つ、文言の定義1つ、`index.astro` への組み込みが中心で、この範囲に収まる見込みである。website.md の更新は仕様の変更であり、行数に数えない。
- **タスクの順序(task-splitter への申し送り)**: website.md の更新(AC-21・AC-22)は spec-designer が担当するタスクとして切る。PBI-002「配色を変える手順」により、「トーン・ビジュアル」節の追記(AC-22)は、トークンの追加(AC-15)を含む実装タスクより**前**(または同じ変更)に完了させる。第3項の書き直し(AC-21)は、本書で内容が確定しているため同じタスクに含めてよいが、実装と矛盾しないことを実装後に確かめる。
- **ヒーローのファーストビュー(AC-18)**: 現在の `main` は `min-h-screen` と縦方向の中央寄せのクラスを持ち、ヒーローだけを画面の中央に置く構成である〔確認: 実行(ファイルの読み出し)。表示の挙動はブラウザで観測していない〕。本セクションを同じ要素の中に単純に追加すると、ヒーローの縦位置が変わる可能性がある(未確認: コードを読んだ推測)。PBI-003 の AC-10(1280 x 800px でヒーロー全体がスクロールせずに見える)を満たし続けることを、PO 確認の前に開発サーバで確かめること。
- **見出しの色**: 基調色 `--color-brand-primary` は、ページ背景の上では 3.353:1 で基準を満たさない。白地の上では 5.001:1 で基準を満たすが、本PBIでは文字色を本文色に統一する(AC-13)。見出しを別の色にする変更は、本PBIの範囲外である。
- **カードの見え方**: 白地とページ背景の明度差は 1.491:1 である。カードの区別は、背景色の差に加えて、カード間の隙間とカード内の余白で伝わる(AC-10)。見出しの構造(AC-3〜AC-5)により、支援技術にもまとまりが伝わる。枠線・影は付けない(本PBIでやらないこと)。
- **最大幅と左端(AC-9)**: 本セクションは、ヒーローのブロックと同じ最大幅(672px)・同じ左端で置く。ヒーローのブロックのコンテナに入れるか、同じ幅の別のコンテナにするかは実装判断。
- **文言の管理**: Markdown で管理する場合、本文の項目をリスト(AC-8)として出力できる形にすること。Markdown の解析用の新しい依存は追加しない(AC-19)。
- **文言の一致**: 確定文言は全角の「％」を含む。入力時に半角の `%` に置き換えないこと(AC-6)。
- **アクセシビリティ**: プロダクト全体の基準は未確定([docs/spec/website.md](./website.md)「未決・後続」)。本PBIで求めるのは、見出しの構造(AC-2〜AC-5)、リストの構造(AC-8)、文字色とコントラスト(AC-13・AC-14)の範囲に限る。本セクションには操作要素を置かないため、キーボード操作の新しい要件は無い。

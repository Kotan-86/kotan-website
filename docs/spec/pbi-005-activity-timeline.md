## 目的(Why)

プロダクトゴール「初対面の人やオンライン上で交流する人が、僕自身の身の丈に合った前向きな印象形成をスムーズに構築できる状態にする」([docs/product-goal.md](../product-goal.md))に対して、現在のページには、ヒーロー(顔写真・名前・一言・SNS 4件)と「僕のコミュニケーション方法」しかない。

- 存在や雰囲気、コミュニケーション方法を知っただけでは、ただの知り合いにしかならない。〔出典: issue #6 の Why〕
- 特に内定式から入社1年目までは、大学以降の活動で**どう楽しんだか**を理解してもらうことが、こーたんという存在を理解してもらうのに重要である。〔出典: issue #6 の Why〕
- そこで、大学入学から現在までの活動と、それぞれの活動の中でどう楽しんだかを、上から新しい順に並べて見せる。

### 設計メモ(実装者への申し送り。実装方法の指定ではない)

- **PBI の大きさ**: [CLAUDE.md](../../CLAUDE.md) の基準は「PBI全体で3コミット程度、1コミットあたりの実装コード変更 300 行まで」。本PBIの実装は、活動歴のコンポーネント1つ、文言の定義1つ、`index.astro` への組み込みと余白の調整が中心で、この範囲に収まる見込みである。website.md の更新は仕様の変更であり、行数に数えない。
- **余白(AC-15)**: 大きさは PO が実装を見ながら決める(PO 決定)。PO 確認で NG が出た場合は、スプリントの「PO確認NGの反復」運用(implementer の po-fix)で調整し、確定版の仕様は全 OK の後に spec-designer が1回だけ書き直す。確定した値は、確定版で AC-15 または設計メモに記録する。
- **ヒーローの上側とファーストビュー(AC-15 の4・AC-17)**: 現在のヒーローは、画面の高さ以上の枠の中で縦中央に置かれている(前提節)。下側だけを小さくする際に、ヒーローのラッパーの縦寄せ・高さの指定を変えると、上側の見え方も変わりうる(未確認: コードを読んだ推測)。PO 確認の前に、開発サーバで、幅 375px と 1280 x 800px のそれぞれについて、変更前と変更後の上側の見え方を見比べ、1280 x 800px でヒーローの全要素がスクロールなしで見えること(PBI-003 AC-10)を確かめること。
- **ヒーローの余白は近似になる(feasibility F-1。承認時に PO へ明示済み)**: ヒーローの上側の見え方を厳密に保ったまま下側だけを小さくすることは、ヒーローの中身の高さが画面幅によって変わるため、静的な CSS だけではすべての画面で厳密には満たせない見込みである(implementer の feasibility による。ブラウザ未観測)。実現は近似でよく、AC-15 は PO 確認で判定する。PO 確認で調整(po-fix)が起きうる。
- **色トークンの検証(AC-19。feasibility F-3)**: Tailwind CSS v4 の自動ソース検出は、仕様書(`docs/spec/*.md`)やコメントも走査しうるため、ビルド済み CSS にクラスや値が**あること**を、活動歴のコンポーネントがそれを**使っている**証拠にしないこと。使用の判定は、コンポーネントのソースと変更差分で行う。また、新規ファイルのコメントに16進の色の値を書くと、AC-19 の直書きの検査で誤検出しうる。
- **時期の改行防止(AC-6・AC-14)**: 時期の文字列を区切り「 - 」の途中で改行させないために、半角スペースをノーブレークスペース(NBSP)などの別の文字に置き換えないこと(AC-6 の完全一致を満たさなくなる)。改行の防止は、文字を変えずに見た目の指定(例: 折り返さない指定 `whitespace-nowrap`)で行う。
- **文言の一致(AC-6・AC-7)**: 本文には半角ピリオド3つの「...」、全角の「？」、「×」、「ヵ」(U+30F5)が含まれる。入力時に「…」(三点リーダー1文字)や半角の「?」、「x」、「ケ」「ヶ」「カ」に置き換えないこと。時期は「表示する時期」の列のとおり、半角ハイフンの前後に半角スペースを1つずつ入れること(Q5)。全角スペースや「〜」「–」「—」に置き換えないこと。
- **点と縦線**: 活動の順序と区切りは、文字(時期・活動名)と見出しの構造で伝わる。点と縦線は装飾であり、支援技術に余計な読み上げをさせないよう配慮すること。
- **アクセシビリティ**: プロダクト全体の基準は未確定([docs/spec/website.md](./website.md)「未決・後続」)。本PBIで求めるのは、見出しの構造(AC-2〜AC-4)、まとまり(AC-5)、コントラスト(AC-12)の範囲に限る。活動歴には操作要素を置かないため、キーボード操作の新しい要件は無い。

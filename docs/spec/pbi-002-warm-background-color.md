# PBI-002: 社員と内定/入社の同期は僕のイメージカラーから親しみやすい温かさと前向きさを感じ取れる

## Issue

#8 — https://github.com/Kotan-86/kotan-website/issues/8

スプリントバックログ上の表記 `PBI-002` は、この issue #8 を指す。

**承認状態: 承認済み(2026-09-22、PO)。承認範囲は受入基準 AC-1〜AC-16 の全体。** 未決の質問は残っていない。本書は、issue #8 の What「文字などは一切変更しない」を本文色1点に限って見直す**レベル3のスコープ変更**を含むため PO の承認を要したが、AC-1〜AC-16 の全体について承認を得た。

## 目的(Why)

プロダクトゴール「初対面の人やオンライン上で交流する人が、僕自身の身の丈に合った前向きな印象形成をスムーズに構築できる状態にする」に対して、**ページを開いた瞬間の第一印象**を担うのが背景色である。

- 現在のページ背景色は基調色 `#606da1` そのものであり、画面の大部分をこの一色が占める。この色は暗めで落ち着いた印象を与えやすく、[docs/spec/website.md](./website.md)「トーン・ビジュアル」が掲げる雰囲気「親しみやすい温かさ + 前向きさ」に対して、温かさ・前向きさの側が弱い。〔出典: issue #8 の Why〕
- 基調色そのものを捨てるのではなく、`#606da1` をベースに薄めて明るくする方向で調整することで、イメージカラーの同一性を保ったまま、印象を「親しみやすい温かさと前向きさ」の側へ寄せる。
- 本PBIは配色の**土台を確定させる**ものでもある。後続PBI(価値観/About、コミュニケーション、いまの自分、アウトプット、私的な面、コンタクトの各セクション)のUI実装は、ここで決まった配色の上に積み増す。配色をいま確定させておくことで、後続PBIで作った画面の色を後から作り直す手戻りを避ける。

### POの意図(確認済み)

出典1: GitHub issue #8 の本文(2026-09-22 時点)。

- 基調色 `#606da1` を**ベースに、薄めて明るくする方針**で背景色を調整する。基調色そのものを別の色相に変える意図ではない。
- 変更された色に合わせて、**仕様書も更新する**。
- **後続PBIのUI実装も、この配色で進める。**

出典2: 2026-09-22、本書の質問 Q1〜Q5(および任意の Q6)への PO 回答。

- **(Q1)** 背景を意図どおり薄くし、**本文色トークン `--color-text-body` も併せて濃い色へ変更する**。issue #8 の「文字などは一切変更しない」は、**本文色の1点に限って見直す**(レベル3のスコープ変更)。それ以外の文字の要素(文言・フォント・サイズ・余白・配置)は、引き続き変更しない。
- **(Q1)** コントラストの基準は、PBI-001 が AC-7 として採用した実績を踏襲し、**4.5:1 以上**とする。
- **(Q2)** 背景色の指定方法は、**混合率(%)方式**を採る。`color-mix(in srgb, var(--color-brand-primary) P%, white)` の形式で、基調色を白で薄めた関係がコードに残る形にする。
- **(Q2)** 具体的な混合率 P と本文色の値は、**本書では確定させない**。実装者が「混合率と対応する本文色」のペアを **2〜3案**作り(いずれもコントラスト比 4.5:1 以上を満たすもの)、**PO が `npm run dev` のローカル画面で実際に見比べて1案を選ぶ**。本書が定めるのは、この**プロセス**と、**満たすべき条件**(コントラスト比 4.5:1 以上、基調色を白で薄めた同系統の色であること)である。
- **(Q2)** 色相を暖色側へ動かす案は採らない。基調色を**白で薄める**操作のみを行う。
- **(Q3)** 基調色 `#606da1` は**配色の導出元**であり、画面上に見える形で残す必要はない。本PBIは「背景色(と本文色)の変更」の範囲に収める。
- **(Q4)** [docs/spec/website.md](./website.md)「トーン・ビジュアル」節は、基調色 / ページ背景色 / 本文色 / 雰囲気の4行に分ける形へ書き換える。具体的な値は上記 Q2 のプロセスで決まるため、**色の選定が完了した時点で確定記述に更新する**(本PBIのタスクとして行う。AC-12)。
- **(Q5)** [docs/spec/pbi-001-site-exists.md](./pbi-001-site-exists.md) は**当時の記録として凍結**し、AC-6・AC-7 を含む本文を書き換えない。同書の「変更理由」末尾に、本PBIで配色が更新された旨と最新の参照先を示す1行を追記するにとどめる(本仕様の更新時に追記済み)。
- **(Q6)** コントラスト基準 4.5:1 を [CLAUDE.md](../../CLAUDE.md) の「DoDの追加項目」へ格上げすることは、**今回は行わない**。本書の「後続PBIのための共有の約束」に記載するにとどめる。[CLAUDE.md](../../CLAUDE.md) は本PBIで変更しない。

## 実現内容(What)

### ユーザーから見えるもの

サイト(ローカル開発サーバおよび公開URL `https://kotan-86.github.io/kotan-website/`)を開いたとき、**ページ全体の背景色が、変更前の `#606da1` より明るく・薄くなっている**。色味は `#606da1` を白で薄めた同系統の色であり、別のイメージカラーに見えるものではない。

それに合わせて、**名前と一言の文字色が、白から濃い色へ変わる**。薄くなった背景の上でも文字がはっきり読める(コントラスト比 4.5:1 以上)状態を保つ。

名前「こーたん（齋藤 光貴）」と一言「割となんでもやりたいが、なんでも出来るわけじゃないジュニアエンジニア」の**文言・配置・文字の大きさ・余白は、変更前と同じ**である。ページに新しい要素は増えない。

### 色の決め方(本PBIの進め方)

背景色の混合率と本文色の組み合わせは、数値だけでは印象を判断できないため、次の順序で決める。

1. 実装者が、**2〜3案**の候補を作る。各案は「背景の混合率 P」と「本文色の値」のペアであり、**いずれもコントラスト比 4.5:1 以上**を満たす。
2. 実装者が、各案の混合率・背景色の概算16進値・本文色の値・コントラスト比の計算値をまとめた比較表を示し、PO が `npm run dev` のローカル画面で各案を実際に見比べられる状態にする。
3. **PO が1案を選ぶ。** 選ばれた案の値を実装に反映する。
4. 選定後に、[docs/spec/website.md](./website.md)「トーン・ビジュアル」節を、確定した値で更新する。

### 配色の確定と共有(ユーザーには見えないが、本PBIの成果物)

- 背景色と本文色を、`src/styles/global.css` の `@theme` トークンとして、それぞれ1か所で定義する。画面側(`.astro`)に16進値を直書きしない(PBI-001 の「後続PBIのための共有の約束」を維持する)。
- 確定した配色を [docs/spec/website.md](./website.md)「トーン・ビジュアル」節に反映し、**後続PBIが参照できる唯一の記述**にする。
- 本書の「後続PBIのための共有の約束」節に、後続PBIのUI実装が守る配色の取り決めを明記する。

### 本PBIでやらないこと

- 新しいセクション・要素・画像・リンクの追加([docs/spec/website.md](./website.md) の第2〜7セクション)。
- レイアウト、フォント、文字サイズ、余白、文言の変更。
- 本文色以外の文字に関する変更(issue #8 の「文字などは一切変更しない」のうち、見直すのは本文色の1点のみ)。
- 基調色 `#606da1` そのものの値の変更(イメージカラーは維持する)。
- 色相を暖色側へ動かす調整(Q2 の決定により対象外)。
- プロダクト全体のアクセシビリティ基準の確定、および [CLAUDE.md](../../CLAUDE.md) への基準の記載(Q6 の決定により見送り)。
- [docs/spec/pbi-001-site-exists.md](./pbi-001-site-exists.md) の本文・AC の書き換え(Q5 の決定により凍結)。
- ダークモード、配色の切り替え機能。

### 色の候補提示と選定

1. **候補が2〜3案そろっている**: 実装者が、背景の混合率 P と本文色の値のペアを 2〜3 案提示し、各案について (a) 混合率 P、(b) 背景色の概算16進値、(c) 本文色の値、(d) 両者のコントラスト比の計算値 が一覧できる比較表になっている。**すべての案で、コントラスト比が 4.5:1 以上である。** どの案の背景色も、基調色 `#606da1` を白で薄めた色(`color-mix(in srgb, var(--color-brand-primary) P%, white)` 相当)であり、色相を動かした色を含まない。〔検証: AI実行(比較表の内容と、各案の16進値からのコントラスト比の再計算)〕

### 見た目

3. **背景が明るくなっている(測定可能)**: 変更後のページ背景色の相対輝度(WCAG 2.x の定義)が、変更前の `#606da1` の相対輝度 0.160 より高い。〔検証: AI実行(採用した色の16進値から計算する)〕

6. **印象が意図どおりに変わっている**: PO がページを開いたとき、変更前と比べて「親しみやすい温かさ + 前向きさ」がより感じられる。〔検証: PO確認〕

### 配色の定義と共有

10. **配色の定義元が1か所である**: ページ背景色と本文色が `src/styles/global.css` の `@theme` トークンとして定義され、`.astro` ファイルに色の16進値の直書きが無い。〔検証: AI実行〕

12. **プロダクト仕様が更新されている**: AC-2 の選定完了後、[docs/spec/website.md](./website.md)「トーン・ビジュアル」節が、(a) 基調色 `#606da1` の位置づけ(配色の導出元であり値を変更しないこと)、(b) 選定したページ背景色(混合式と概算16進値)、(c) 本文色の値と、背景色とのコントラスト比、(d) 雰囲気「親しみやすい温かさ + 前向きさ」の4点を記載しており、本書の決定内容および `src/styles/global.css` のトークン値と矛盾しない。**本PBIの完了時点でこの状態になっていること**(選定前の時点で未更新であることは、本ACの違反としない)。〔検証: AI実行〕

### 設計メモ(実装者への申し送り。実装方法の指定ではない)

- **候補作成の出発点**: 上記「前提」の実測表(混合率 P ごとに 4.5:1 を満たす最も明るい本文色)が、候補作成の材料になる。P が大きい(濃い)ほど本文色はほぼ黒に近づき、P が小さい(薄い)ほど本文色の選択肢が広がる。2〜3案は、印象の違いが PO に伝わる程度に離れた P を選ぶとよい(例: 濃いめ・中間・薄めの3点)。
- **「温かさ」と色相について(観測に基づく補足)**: `#606da1` を白で薄める操作は、明度と彩度を動かすが、色相(青紫系=寒色)は変わらない。「親しみやすさ」「軽やかさ」は増すが、色温度の意味での「温かさ」は増えない。色相を暖色側へ動かす案は、Q2 の決定により本PBIの対象外である。
- **PBI-001 の AC-6 との関係**: PBI-001 の AC-6 は「ページの配色に `#606da1` が(背景・文字色・装飾のいずれかとして)使われている」ことを求めていた。Q3 の決定により、`#606da1` は配色の導出元として `--color-brand-primary` に残り、画面上に現れる必要はない。本PBIでは、イメージカラーの同一性を AC-5(PO確認)で引き継ぐ。PBI-001 の仕様書は凍結し、当時の記録として残す(Q5)。

- issue #8(2026-09-22 起票): スプリント002「warm-background-color」のリファインメントとして新規作成。issue #8 の Why / What を仕様化し、現行実装のカラートークンとコントラスト比を実測したうえで、「背景のみを薄くして文字を変えない」と「コントラスト比 4.5:1 以上」が両立しないという観測事実を前提節に記録した。未決の質問 Q1〜Q5(および任意の Q6)を起票し、受入基準は案(未承認)のままとした。
- issue #8(2026-09-22 PO決定 Q1〜Q6 の反映): PO の決定を反映し、受入基準を確定案に書き直した。主な内容は次のとおり。
  - **レベル3のスコープ変更**: Q1 の決定 B により、issue #8 の What「文字などは一切変更しない」を、**本文色トークン `--color-text-body` の1点に限って見直す**。背景を意図どおり薄くし、本文色を濃い色へ変更する。それ以外の文字に関する変更は引き続き行わない。コントラストの基準は 4.5:1 以上(PBI-001 AC-7 の踏襲)。
